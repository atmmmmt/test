# رفقة العمرة — بث مباشر محلي (PWA)

نسخة PWA تجريبية موسعة للبث **المباشر فقط**. لا تسجيلات ولا تخزين للصوت على خادم.

## ماذا يشتغل الآن في الكود؟

- واجهة عربية RTL متجاوبة، وثلاثة أدوار: شيخ، مستمع، جهاز وسيط.
- التقاط ميكروفون الشيخ وتشغيل الصوت في المستمع عبر WebRTC.
- عدة اتصالات WebRTC صادرة من الشيخ أو الجهاز الوسيط بدلاً من حد المستمع الواحد السابق.
- جهاز وسيط يستطيع استقبال مسار صوت وتحويله إلى اتصالات مستمعين آخرين، إذا دعم الجهاز والشبكة هذا السيناريو.
- ربط يدوي ثنائي الاتجاه عبر رموز QR مجزّأة أو نسخ/لصق SDP.
- إحصاءات الشبكة، وحالة اتصال كل جهاز، وكتم ميكروفون الشيخ، وإنهاء الجلسة.
- PWA + Service Worker لتخزين واجهة التطبيق لاستخدامها دون إنترنت بعد الزيارة الأولى.
- لا يستخدم MediaRecorder ولا قاعدة بيانات صوتية.

## حدود ضرورية قبل استخدامه بالعمرة

**لا يستطيع PWA تكوين Bluetooth/Wi-Fi Mesh تلقائي بين أجهزة iOS وAndroid.** تحتاج كل الهواتف إلى شبكة IP محلية تسمح بالاتصال المباشر بينها، مثلاً Wi-Fi محلية أو Hotspot (ولو بلا إنترنت). إذا لم توجد أي شبكة محلية فلن يُبث الصوت. الربط اليدوي لكل وصلة يأخذ وقتاً، لذلك هذه ليست طريقة جاهزة لخدمة 100 شخص.

- دعم عدد كبير، والتأخير، واستمرار الصوت والشاشة مقفلة، وتبادل الاتصال عبر عدة قفزات: **غير مثبتين** ويحتاجون اختباراً فعلياً.
- WebRTC مضبوط على `iceServers: []`، لذا لا توجد خدمات STUN أو TURN ولا عبور بين شبكات منفصلة.
- مستخدم iOS يحتاج فتح الموقع أولاً على HTTPS بوجود إنترنت وتثبيت PWA قبل السفر؛ وأذونات الكاميرا والميكروفون لا تُمنح مسبقاً دائماً.
- لا توجد مصادقة قوية للشيخ ولا تحكم بمصدر الصوت عند السماح لأشخاص غير موثوقين بالمسح؛ تجنب مشاركة رموز QR مع الغرباء.
- اعتماد 100 مستمع، خصوصاً على Hotspot هاتف واحد، **غير مضمون ولا ينصح به**.
- النسخة تجريبية تقنية وغير مختبرة على أجهزة فعلية حتى الآن.

## التشغيل والتوزيع

```bash
npm install
npm run typecheck
npm run build
npm run dev
```

انشر المشروع على HTTPS باستخدام منصة متوافقة مع Next.js. افتح التطبيق على كل هاتف بينما الإنترنت موجود، وبعدها أضفه للشاشة الرئيسية. اختبر فتحه Offline قبل الرحلة.

### تجربة 3 أجهزة

1. هاتف الشيخ وهاتف الوسيط وهاتف المستمع على **نفس Wi-Fi المحلي**.
2. على الشيخ: اختر «الشيخ» ثم «بدء البث»، وبعدها «إضافة مستمع أو جهاز وسيط».
3. على الوسيط: اختر «جهاز وسيط»، وامسح **كل صفحات QR** المعروضة من الشيخ.
4. الوسيط يعرض رموز الرد؛ الشيخ يمسحها. بعدها الوسيط يستقبل صوت الشيخ.
5. على الوسيط اضغط «إضافة مستمع» لفتح وصلة ثالثة.
6. المستمع يمسح QR الوسيط ويعرض رموز الرد، والوسيط يمسحها.
7. المستمع يضغط «تشغيل صوت الشيخ».
8. قيّم التقطيع، تأخير الصوت، واستهلاك البطارية، ثم كرّر على iPhone وAndroid.

### بنية العمل

- `components/GroupApp.tsx`: منطق الصوت وأدوار المجموعة وإدارة WebRTC وQR.
- `app/group.css`: واجهة الجلسة.
- `app/page.tsx`: دخول التطبيق.
- `public/sw.js`: حفظ واجهة PWA.
- `components/LiveApp.tsx`: تجربة أصلية محفوظة كمرجع فقط.

## درجة الجاهزية

هذه **نسخة MVP قابلة للتجربة** وليست نظاماً معتمداً لخدمة 100 شخص دون إنترنت. يجب إجراء اختبار تأكيد الاتصال على هاتفين وثلاثة هواتف قبل تطوير توجيه Mesh حقيقي، ثم اختبارات على 10/30/100 جهاز.
