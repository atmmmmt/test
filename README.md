# رفقة العمرة | تسجيل المشاركين وإدارة المجموعات

## تجربة المستخدم
- افتح رابط دعوة واحد يحتوي على كود الرحلة، واكتب اسمك وحدد (مشارك / متطوع للتنظيم).
- يتم إرسال التسجيل فعلياً إلى API على Vercel مع تخزين خاص Vercel Blob. عند انعدام الإنترنت يحفظ التطبيق مسودة محلية فقط ولا يدّعي إرسالها.
- يحتفظ المتصفح ببطاقة العضوية السرية والاسم والمجموعة على الجهاز، ويجلب آخر التوزيع عند وجود إنترنت.
- المسؤول يدخل برمز إداري سري، ويعرض كل الأسماء والأشخاص بانتظار الفرز، يوزعهم يدوياً أو تلقائياً، ويختار مسؤولي المجموعات. ويستطيع مشاركة دعوة QR وتصدير CSV.
- يقدّم زر تثبيت PWA المتاح على أندرويد، ويعرض خطوات «إضافة للشاشة الرئيسية» على الآيفون؛ تثبيت التطبيقات دون موافقة المستخدم غير متاح.

## البنية
- `/` التسجيل + لوحة الإدارة.
- `/api/roster` POST التسجيل، GET الإدارة، PATCH التوزيع.
- `/api/me` فحص بطاقة العضوية.
- `lib/roster.ts` تخزين الأعضاء بوثائق JSON خاصة في Vercel Blob.
- `/lab` تجربة WebRTC صوتية قديمة تتطلب شبكة Wi-Fi محلية، وليست الشبكة العنكبوتية المطلوبة.

## المتغيرات المطلوبة في Vercel
- `BLOB_READ_WRITE_TOKEN` من private Blob store.
- `UMRAH_ADMIN_PIN` رمز المسؤول (متغير مشفر).
- `UMRAH_JOIN_CODE` رمز الدعوة، موجود ضمن رابط الأعضاء ولا يتطلب إدخاله يدوياً إذا استعملوا الرابط.

## الملاحظات التقنية
- التسجيل والتوزيع والمزامنة بين الأجهزة تحتاج إنترنت **قبل العمرة**. بعد آخر تحديث، البطاقة المحفوظة محلياً متاحة دون إنترنت.
- لا يوجد في PWA بث صوت مباشر عبر Bluetooth Mesh على آيفون وأندرويد، ولا يمكن تثبيت تطبيق صوتي خارجي تلقائياً. هذا النظام لإدارة الأشخاص وليس بديلاً عن تقنية البث.
- قائمة الأسماء محمية برمز الإدارة؛ البيانات مخزنة في Blob خاص وليست عامة. هذا MVP لتنظيم رفقة محدودة، وليس نظام هويات رسمي. يلزم اختبار صلاحيات الإدارة وضبط سياسة الاحتفاظ بالبيانات.
- الحد النظري للمجموعة هنا 16، ويتطلب نجاح أي توزيع صوتي مستقل تجربة ميدانية.
- يفضل توزيع 100 جهاز من قبل المنظم خلال اتصال الإنترنت قبل الرحلة.
